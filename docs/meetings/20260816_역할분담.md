## 남은 일

### 성현 — 이게 제일 급하다

**1. 매칭 점수에 변별력이 없다**

실제 공고로 돌리면 24건 중 상당수가 **100점**이다. `지역 충족` 조건
하나만 맞아도 만점이 나온다. 손으로 만든 샘플 19건은 조건이 촘촘했는데
진짜 공고는 그렇지 않아서 변별력이 사라졌다.

> 심사위원이 "왜 다 100점이냐"고 물으면 답이 궁색하다.
> **AI 매칭이라는 주장 자체가 흔들리는 지점**이다.

조건이 적은 공고에 만점을 주지 않는 방식이 필요하다. 도메인을 아는
사람이 판단할 문제라 성현 몫이다.

**2. OCR 후처리** — 업태 `종목`이 `종콩]`으로 읽힌다. 화면에 그대로 나온다.

**3. 시연 영상** — 소상공인을 직접 해봤으니 "사장님이 실제로 겪는 순간"을
팀에서 제일 잘 쓴다. 시나리오부터 잡아줄 것.

### 서희 — 화면

**1. 공고 상세 화면이 없다**

지금 `자세히 →`를 누르면 공고를 못 보고 서류 체크리스트로 바로 넘어간다.
공고를 읽는 화면이 아예 없다.

여기에 들어갈 것: 조건 판정 결과 · 어려운 말 풀이 · **접수처**.
수집한 25건 **전부** 문의처가 공고 낸 기관과 다르다. 그게 우리 근거인데
지금은 그걸 푸는 자리가 비어 있다.

**2. 사업자등록증 업로드 화면**

서버(`POST /api/business-registration`)와 OCR 413줄은 **이미 있다.**
프론트에서 부르는 곳이 0건이라 시연을 못 한다.
첫 호출이 78초라 **기다리는 화면이 반드시 필요하다.**

**3. `find.png`** — 올렸는데 쓰는 곳이 없다. 어디에 쓸 것인지 확인.

**4. 발표 슬라이드 디자인** — 내용은 대윤이 준다. 8/19.

## 시연 동선 (3분)

```
랜딩 → 둘러보기(로그인 생략) → 조건 4단계
  → 대시보드에서 매칭이유 ▼ 펼치기      ← 여기가 핵심
  → 공고 상세에서 접수처 보여주기
  → 신청 동행 서류 체크리스트
  → 챗봇에서 노란 용어 짚기
```

**매칭이유를 펼치는 장면**이 없으면 그냥 목록 서비스로 보인다.
사업자등록증 업로드가 붙으면 맨 앞에 넣는다 — 사진 한 장으로 조건이
채워지는 장면이 제일 강하다.

OCR 은 Vercel 에 안 올라간다(torch 1.4GB, 한도 250MB).
**노트북에서 로컬 서버로 시연**하고 영상에 담는다.
