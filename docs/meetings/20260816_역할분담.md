## 기획서에 대한 판단 (성현 `docs/온보딩_기획서.txt`)

기획은 좋다. 특히 **"스킵한 필드는 확인필요로 처리"** 원칙은 대윤이 공고
쪽에 적용한 방식과 정확히 같다. 사용자가 안 답한 것과 공고문에서 못 읽은
것을 똑같이 "모른다"로 다루는 게 맞다.

**다만 4일에 다 못 한다.** 기획서가 요구하는 신규 작업은 이 정도다.

| | 분량 |
|---|---|
| 온보딩 A·B·C 경로 분기 | 화면 7~9개 (현재 4단계) |
| 마감 캘린더 | 신규 |
| 상권 분석 | 신규 |
| 하단 네비게이션 | 신규 |
| 전체 공모 목록 · 캘린더 전체 · 내 정보 | 신규 3화면 |
| 공고 상세 | 신규 |

서희 한 명이 4일에 할 분량이 아니다. **1차에 넣을 것을 골라야 한다.**

### 1차에 넣을 것

1. **경로 C (사업자등록증 OCR)** — 서버와 OCR 413줄이 이미 있다.
   사진 한 장으로 조건이 채워지는 장면이 시연에서 제일 강하다.
2. **공고 상세** — 접수처 불일치 100%가 우리 근거인데 지금 보여줄 자리가 없다.
3. **사용자 요약 칩** — 만들기 쉽고 "내 조건으로 찾았다"가 눈에 보인다.

### 2차 예선으로 미룰 것

마감 캘린더 · 하단 네비게이션 · 전체 공모 목록 · 경로 A/B 분기.
Q1 분기 없이 지금의 4단계를 유지해도 시연에는 지장이 없다.

### 상권 분석은 넣지 말 것

기획서에 **"수치는 정적 데이터로 하드코딩 후 추후 연동"** 이라고 돼 있다.
"화성시 카페 347개" 같은 숫자를 지어내면 안 된다.

우리 발표 전체가 **"우리가 직접 재서 나온 숫자"** 위에 서 있다. 근거 있는
숫자 옆에 지어낸 숫자를 놓으면 둘 다 의심받는다. 심사위원이 "그 347개는
어디서 나왔냐"고 물으면 답할 게 없다.

넣으려면 실제로 세야 하고, 4일 안에는 어렵다. 2차로 미루는 게 맞다.

### 기존 코드와 어긋나는 것

| 기획서 | 현재 | 처리 |
|---|---|---|
| `region: 화성시 / 경기도 / 타지역` | 2개만 | 매칭 엔진에 `타지역` 추가 필요 — 대윤 |
| 저장은 localStorage | Supabase + 카카오 구현됨 | 비로그인 localStorage, 로그인 서버로 — 대윤 |
| `onboarding_path` 필드 추가 | 없음 | 매칭 엔진이 모르는 키는 버리므로 무해 |

## 시연 동선 (3분)

```
랜딩 → 둘러보기(로그인 생략) → 조건 4단계
  → 대시보드에서 매칭이유 ▼ 펼치기      ← 여기가 핵심
  → 공고 상세에서 접수처 보여주기
  → 신청 동행 서류 체크리스트
  → 챗봇에서 노란 용어 짚기
```

**매칭이유를 펼치는 장면**이 없으면 그냥 목록 서비스로 보인다.
사업자등록증 업로드가 붙으면 맨 앞에 넣는다 — 사진 한 장으로 조건이
채워지는 장면이 제일 강하다.

OCR 은 Vercel 에 안 올라간다(torch 1.4GB, 한도 250MB).
**노트북에서 로컬 서버로 시연**하고 영상에 담는다.
