# 공고 수집 소스와 커버리지

어디서 무엇을 가져왔고, **무엇을 못 가져왔는지** 적은 문서다.
못 가져온 쪽이 더 중요하다. 발표에서 질문이 거기서 나온다.

측정 기준일: **2026-08-15**. 기업마당 API는 실시간이라 숫자가 매일 바뀐다.

---

## 1. 기업마당 (bizinfo.go.kr) — 지금 쓰는 소스

중소벤처기업부가 운영하는 정부 지원사업 통합 공고 사이트다.
중앙부처·지자체·공공기관 공고가 한곳에 모인다.

```
GET https://www.bizinfo.go.kr/uss/rss/bizinfoApi.do
```

| | |
|---|---|
| 인증키 | bizinfo.go.kr 에서 발급 (**data.go.kr 아님**) |
| 로그인 | onepass.smes.go.kr — 중소벤처24 통합계정 |
| 키 보관 | 저장소 루트 `.env` 의 `BIZINFO_API_KEY`. gitignore 돼 있다 |
| 코드 | `collect.py` |

### 받은 결과

```
전체 공고              1,539건
└ 소상공인 관련          269건
   ├ 화성시 전용           4건   ← 그중 1건은 농업인 대상이라 실제로는 3건
   └ 화성시민이 신청 가능   62건   (전국 + 경기전체 + 화성)
        그중 현재 접수중     31건
```

여기서 요건까지 추출해 쓸 수 있는 공고로 정리한 것이 **25건**이다
(`notices/`). 재현은 `collect.py --coverage`.

### 알아둘 것

**지역 해시태그가 시/도 단위까지만 있다.** `경기`는 되지만 `화성`은 없다.
그래서 경기 전체를 받아서 공고명·개요로 걸러낸다.

**문서와 실제 응답이 다르다.** 두 군데서 당했다.

| 항목 | 문서 | 실제 |
|---|---|---|
| 신청기간 | `20260813` | `2026-08-13 ~ 2026-08-24` |
| 해시태그 필드 | `hashTags` | `hashtags` |

`collect.py` 는 양쪽을 다 받게 해뒀다. 나중에 응답이 또 바뀌면
`--peek` 로 구조부터 확인할 것.

**제목의 `[지역]` 표시를 믿으면 안 된다.** 표시 없이 들어오는 지역 전용
공고가 있다. 실제로 광주·서울 전용 공고 2건이 화성 사용자에게
'신청가능 100점'으로 떴다. 지금은 소관기관도 같이 본다 (`scope()`).

수행기관은 일부러 안 본다. 소담스퀘어처럼 중앙부처 사업을 지역 기관이
대행하는 경우가 있어서, 수행기관까지 보면 전국 사업을 지역 전용으로
잘못 자른다.

**요건은 API 응답에 없다.** 사업개요는 200~400자 요약이라
"창업 7년 이내", "휴·폐업 중 제외" 같은 실제 조건은 첨부 공고문에만 있다.
그래서 `fetch_docs.py` 로 첨부를 따로 받는다.

### 첨부 공고문 — 절반 이상이 기계로 안 읽힌다

접수중 31건 중 **13건(42%)** 만 텍스트를 뽑았다.

| 못 읽은 이유 | 건수 |
|---|---|
| 스캔 PDF (이미지만 들어있음) | 6 |
| HWP (한글 구버전) | 7 |
| 이미지 파일 | 5 |

- PDF → `pdftotext -layout` 로 처리
- HWPX → ZIP 안의 OWPML XML, `<hp:t>` 에서 텍스트를 뽑는다
- **HWP는 처리 못 한다.** pyhwp / soffice / olefile 이 이 서버에 없다

스캔 PDF·이미지 11건은 OCR로 뚫을 수 있다. 성현이 만든 easyocr 코드를
재사용하면 된다. **아직 안 했다.**

## 2. 화성시청 고시공고 — 백업 소스, 아직 안 씀

```
목록  https://www.hscity.go.kr/www/gosi/BD_selectGosiList.do?q_cp=1
상세  https://www.hscity.go.kr/www/gosi/BD_selectGosiDetail.do?q_notAncmtMgtNo=<번호>
```

`robots.txt` 는 `/www/gosi/` 를 막지 않는다 (2026-08-15 확인).
`/foreign` `/minwon` `/citizen` 등이 막혀 있고 고시공고는 허용이다.

한 페이지에 10건씩 나오고, 상세는 `opGosiView(번호)` 로 넘어간다.

> **중요 — 우리는 이 소스를 아직 수집하지 않았다.**
> 구조만 확인했고 크롤러는 만들지 않았다. `policy_data/` 에 화성시청
> 관련 코드도 데이터도 없다.

### 발표 자료의 "9,467건" 은 근거가 없다

`docs/서비스_필요성_근거.md` 에 "화성시청 고시공고 9,467건을 실제로
수집·분석했다"고 적혀 있는데, **저장소에 그 근거가 없다.**
목록 페이지 HTML에도 총 건수가 안 나온다.

같은 문서에 "출처 없는 숫자는 발표에서 쓰지 않는다"고 써놓고 이걸
어긴 셈이다. 심사위원이 "그 9,467건 어떻게 세셨어요" 하면 답할 게 없다.

**둘 중 하나를 해야 한다.**
1. 크롤러를 만들어서 실제로 세고 근거를 남긴다
2. 발표 자료에서 그 숫자를 뺀다

기업마당 수치(1,539 / 269 / 62 / 31)는 `collect.py --coverage` 로
언제든 재현되므로 문제 없다. 9,467만 걸린다.

### 왜 백업 소스로 남겨뒀나

화성시가 직접 하는 소상공인 지원사업은 기업마당 기준 연 3건뿐이다.
시청 고시공고에는 기업마당에 안 올라오는 공고가 있을 수 있다.
다만 지금은 전국·경기 공고까지 합쳐 62건을 확보했으므로 급하지 않다.

## 4. 검색 방식 — 키워드보다 부서 기준

공고 제목에 "소상공인"이 안 들어가는 경우가 많다.

```
2026년 화성시 사회적경제기금 융자지원사업     ← 소상공인 대상인데 제목에 없다
2026년 동탄 소공인복합지원센터 인프라 지원    ← '소공인'
```

그래서 `SOSANG` 정규식을 넓게 잡았다.

```python
소상공인|자영업|점포|소공인|골목|상점가
```

제목만 보지 않고 개요·대상·해시태그를 합친 문자열(`haystack()`)에서 찾는다.

### 반대로 넓게 잡으면 안 되는 것도 있다

제외 규칙은 좁게 잡아야 한다. 한 번 크게 당했다.

```
"재해·재난을 직접 원인으로 휴업중인 소상공인 제외"
```

이건 **제외 규정의 예외**를 적은 문장인데, 처음엔 "소상공인 제외"로 읽혀서
정작 소상공인 대상 공고가 통째로 빠졌다. 지금은 표준 문구
`소기업(소상공인)…지원 제외` 만 잡는다.

## 재현

```bash
python3 policy_data/collect.py --peek       # 응답 구조 확인
python3 policy_data/collect.py --coverage   # 1,539 / 269 / 3 / 62 / 31
python3 policy_data/collect.py --raw        # 원본을 raw/ 에 저장
python3 policy_data/fetch_docs.py           # 첨부 공고문 → raw/docs/
python3 policy_data/extract.py              # notices/ 에 25건 생성
python3 policy_data/validate.py             # 매칭 엔진에 넣어서 검사
```

`raw/` 는 4MB에 매일 바뀌므로 gitignore 돼 있다. 위 순서대로 다시 돌리면 된다.
