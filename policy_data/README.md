# 공고 데이터 수집·가공

담당: 대윤

- 정책/공고문 가져오기 (크롤링 또는 API — 방식은 재량)
- 공고에서 지원 요건 추출 (연령, 매출, 위치, 창업 경험 등)
- 행정 용어 사전 만들기
- 신청 시 필요한 서류를 어디서 어떻게 발급·준비하는지 정리

산출물은 `matching/notices/` 와 같은 JSON 형식으로 맞춘다.

---

## 파일

| 파일 | 내용 |
|---|---|
| `schema.md` | 공고 JSON 규격. `matching.py` 코드에서 뽑은 것 |
| `validate.py` | 수집한 공고를 실제 매칭 엔진에 넣어보는 검사기 |
| `terms.json` | 행정용어 사전 (용어 26개 · 서류 20개) |
| `terms.py` | 사전 조회 — 공고문에서 용어 찾기, 서류 발급 안내 |
| `notices/` | 수집한 공고 JSON |

---

## 행정용어 사전

공고문의 어려운 말을 쉬운 말로 바꾸고, 요구 서류를 **어디서 어떻게 떼는지**까지 알려준다.
이게 우리 서비스의 차별점이라 정확도가 중요하다.

### 원칙

- **실제 공고에 나온 용어만 넣는다.** 각 항목의 `seen_in` 에 어느 공고에서 봤는지 적혀 있다.
- **확인 안 된 건 `verified: false` 로 표시한다.** 발급처를 틀리게 적으면 서비스 신뢰가 무너진다.
  `terms.py --stats` 로 확인 필요 항목을 볼 수 있다.
- 서류는 **발급받는 것**(사업자등록증명)과 **직접 만들거나 업체에서 받는 것**(견적서, 시공 전 사진)을
  구분한다. 후자는 시간이 걸려서 미리 알려주지 않으면 마감을 놓친다.

### 쓰는 법

```bash
python3 policy_data/terms.py --demo                 실제 공고로 시연
python3 policy_data/terms.py "공고 본문"             텍스트에서 용어 찾기
python3 policy_data/terms.py --file 공고.txt         파일에서 찾기
python3 policy_data/terms.py --doc 사업자등록증명      서류 발급 안내
python3 policy_data/terms.py --stats                사전 현황 + 확인 필요 목록
```

### 코드에서 부를 때

```python
import sys; sys.path.insert(0, "policy_data")
from terms import find_terms, find_document, glossary_for

find_terms(공고본문)        # 본문에 실제로 나온 용어만 (등장 순서대로)
find_document("매출 증빙자료")  # → 부가가치세 과세표준증명 발급 안내
glossary_for(공고본문)       # LLM 프롬프트에 넣을 문자열
```

`glossary_for()` 를 쓰면 **사전 전체가 아니라 그 공고에 나온 용어만** 프롬프트에 들어간다.
토큰도 아끼고 엉뚱한 용어를 끌어다 쓰는 것도 막는다.

`find_document()` 는 별칭과 부분일치까지 본다. 매칭 엔진이 뱉는 서류명 32종 중
30종이 사전 항목으로 연결된다 (`시공 전 사진` → `현장 사진`, `POS 도입 견적서` → `견적서`).

### 새 용어를 넣을 때

`terms.json` 에 추가하고 `--stats` 로 확인한다. 필수는 아니지만 채워두면 좋은 것:

- `aliases` — 공고마다 표기가 다르다 (`이차보전` / `이차차액보전` / `이자차액보전`)
- `caution` — 사람들이 실제로 실수하는 지점. 이게 제일 값어치 있다
- `seen_in` — 어느 공고에서 봤는지. 나중에 근거를 되짚을 수 있다

## 공고 수집

키워드 검색보다 **부서 기준**이 낫다. 공고 제목에 "소상공인"이 안 들어가는 경우가 많다
(예: `2026년 화성시 사회적경제기금 융자지원사업`).

수집 소스와 커버리지 조사 결과는 `sources.md` 참고.
