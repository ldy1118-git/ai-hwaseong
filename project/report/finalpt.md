## 2장 — 돈은 역대 최대다

**화면** — 숫자 하나

```
          5.4조 원
  2026년 소상공인 지원 예산
```

**말할 것:**

- 중소벤처기업부 2026년 소상공인 지원사업 통합공고. 7개 분야 26개 사업
- 직접 지원 1조 3,410억 + 정책자금 3조 3,620억
- "돈이 없어서 못 받는 게 아닙니다."

그런데 여기에 한 문장 더 붙인다:

> "화성시는 경기도에서 사업체 수가 가장 많은 도시입니다. 약 14만 4천 개의 사업체, 그중 상당수가 소상공인이고 이 돈의 수혜 대상입니다."

출처: 화성특례시 2025년 경제총조사 (사업체 약 144,173개, 경기도 최대)  
⚠️ "소상공인 수"가 144,173개라고 하면 안 됨 — 전체 사업체 수. 그대로 인용할 것.

## 3장 — 그런데 3.2%만 받는다

**이 발표의 중심 슬라이드.**

**화면** — 숫자 셋

```
   3.2%          76.2%         87.5%
참여했다     "몰라서 못 했다"    만족했다
```

**말할 것:**

> "디지털 전환 지원사업의 경우, 실제로 참여한 소상공인은 3.2%입니다. 참여 못한 이유 1위는 '정책 자체를 알지 못했다' 76.2%입니다. 그런데 써본 사람은 87.5%가 만족합니다."

**반드시 "디지털 전환 지원사업의 경우"를 붙일 것.** 출처: 중소기업중앙회, 소상공인 디지털 전환 실태조사, 2026, 500개사. 이 조건을 빼고 말하면 반박 한 번에 무너진다.

> "좋은 제도인데 → 몰라서 못 쓰고 → 쓴 사람은 만족한다. 정보 전달만 고치면 되는 문제입니다."

시간이 되면 한 문장 더:
> "5년 생존율은 40.2%입니다. 본인 돈 5,900만 원을 넣고 시작한 사람들이에요. 지원사업을 석 달 늦게 아는 게 그 사람에겐 치명적입니다."

출처: 국세청 100대 생활업종 통계

## 4장 — 시청만 봐서는 못 찾는다

**4~6장은 남의 통계가 아니라 우리가 직접 재서 나온 1차 자료다. 이걸 강조할 것.**

**화면**

```
    4건     vs     64건
화성시 직접       화성시 소상공인이
하는 지원사업     실제 신청 가능한 공고
```

**말할 것:**

- 화성시가 직접 하는 지원사업은 4건
- 전국·경기도 대상 공고 중 화성시 소상공인이 신청할 수 있는 건 64건
- **"16배 차이입니다. 시청 홈페이지만 보는 소상공인은 신청할 수 있는 공고의 95%를 못 봅니다."**

출처: 기업마당 API + 화성시청 크롤링 직접 수집 (기준일 2026-08-19)

## 5장 — 검색해도 안 나온다

**화면**

```
9,458건  →  67건  →  17건
 고시공고     '소상공인'    실제 지원사업
  전체        검색결과      (0.18%)

       67건 중 50건이 대형마트 입점 예고
```

**말할 것:**

> "화성시청 고시공고 9,458건을 전부 받아 '소상공인'으로 검색하면 67건이 나옵니다. 그중 50건이 이마트·GS더프레시 같은 대형마트 입점 예고입니다. 유통산업발전법 의무 공고라 담당부서만 소상공인과일 뿐, 신청해서 받는 사업이 아닙니다."

그리고 결정타:

> "게다가 제목이 '중소기업 운전자금'이면 아예 검색에 안 걸립니다. 소상공인도 신청 대상인데 제목이 달라서 빠진 공고가 10건 확인됐습니다. **키워드 검색으로는 찾을 수 없는 구조입니다. 그래서 조건으로 매칭해야 합니다.**"

출처: hscity.py로 게시판 946페이지 직접 수집 (2026-08-19 기준). 17건·10건은 제목만 보고 센 하한값.

## 6장 — 찾아도 두 가지가 막힌다

**화면**

```
   100%           10곳          29종
문의처가 공고 낸   신청 사이트가   요구되는
기관이 아니다      흩어져 있다     서류 종류
```

**말할 것 — ① 어디에 내는지 모른다**

- 수집한 공고 29건 전부, 소관기관과 실제 접수 수행기관이 다르다
- "시청에 전화하면 '저희 소관 아닙니다'라는 답을 듣습니다"
- 신청처가 10개 사이트에 흩어져 있다. 기업마당 · 경기플랫폼 · 소상공인지24 · 한국문화진흥원 · 중소기업중앙회 · HACCP · **그중 한 건은 네이버 폼(naver.me)이다.**

**말할 것 — ② 서류 준비가 복잡하다**

- 공고 1건당 제출서류 평균 3.6종, 최대 14종
- 전체 서류 종류 29종
- 공고문의 절반 이상이 기계로 못 읽는다 — HWP·스캔 이미지·텍스트층 없는 PDF
- "정보가 없는 게 아니라, 있는데 읽을 수가 없습니다."

6장을 이 한 문장으로 닫고 7장으로 넘어간다.

# 2부 · 해결과 시연 (5분)

## 7장 — 서비스 한 장

소상공인이 겪는 순서로 묶는다. 기능 목록 나열 금지.

```
  찾는다    →  공고 자동 수집 · 조건 맞춤 추천
  읽는다    →  용어 설명 · AI 요약 · 챗봇
  낸다      →  서류 체크리스트 · 접수처·신청 링크 바로가기
  관리한다  →  세무 일정 · 상권 분석          ← 2차 고도화
```

**말할 것:**

- 앞의 셋이 4·5·6장의 문제에 하나씩 대응한다
- 마지막 "관리한다"는 다음 단계 — 세무 일정은 데이터 완료, 상권분석은 현재 목업

이 구조라면 세무·상권이 아직이어도 **"빠진 게 아니라 다음 단계"** 로 보인다.

## 8장 — 시연 ① 조건을 입력하면 내 공고만

**흐름**: 온보딩 → 홈 대시보드

**핵심 포인트:**

- 온보딩: 한 번에 다 묻지 않는다. 업종 → 창업 상태 → 이후 순서대로. 사업자라면 세무 질문 3개 추가
- 결과가 신청가능 / 확인필요 / 대상아님으로 나뉜다
- 카드에 AI 한 줄 요약이 붙는다 (왜 내 카드에 떴는지 바로 파악)
- **"검색이 아니라 자격요건을 읽어서 판정합니다"** — 5장의 키워드 문제에 대한 답

같은 서비스에서 조건만 바꾸면 결과가 달라지는 걸 보여준다:

| 프로필 | 신청가능 | 확인필요 | 대상아님 |
|---|---|---|---|
| 예비창업 카페 (화성시) | 4 | 16 | 9 |
| 운영중 음식점 (화성시 24개월) | 13 | 16 | 0 |
| 운영중 소매업 (경기도 60개월) | 12 | 14 | 3 |

출처: /api/match 실제 결과 (2026-08-19 기준 29건 공고)

## 9장 — 시연 ② 공고를 풀어서 읽어준다

**흐름**: 카드 "자세히 보기" → NoticeDetail 화면

**핵심 포인트:**

- 공고 조건 판정 결과 ("내 조건과 맞춰본 결과" 섹션)
- 행정용어 자동 감지 → 31개 용어 사전에서 쉬운 말로 설명
- 서류 목록 → 26개 서류 사전에서 발급처·비용·소요시간 안내
- 접수처와 소관기관이 다를 때 따로 표시 — 6장의 100% 문제에 대한 답

**말할 것:**

> "공고문을 그대로 보여주는 게 아니라, 알아들을 수 있게 바꿔줍니다."

## 10장 — 시연 ③ 뭘·어디서·어떻게 내는지

**흐름**: NoticeDetail 하단 → "서류 준비하기" → ApplicationGuide

**핵심 포인트:**

- 공고별 제출 서류 목록 (Groq + RAG → 서류별 발급처·URL·비용)
- RAG 매칭률 100% (15개 서류 전부 terms.json에서 매칭)
- URL 포함: baseline 0개 → v1 4개 (RAG 없으면 발급처를 알 수 없음)

# 3부 · 차별점 (1분)

## 12장 — 왜 우리 팀인가

**세 가지 축으로 정리한다.**

### 축 1: 공백 시장 — 전국형 서비스가 못 하는 것을 한다

```
기업마당 · 소진공포털 · 콜센터      우리 서비스
────────────────────────          ────────────────────────
전국 단위 공고 목록 제공           화성시 소상공인에게
"이런 공고가 있습니다"로 끝남       신청 가능한가 판정
키워드 검색에 의존                 조건 매칭으로 판정
화성시청 공고 미통합               기업마당 API + 화성시청 크롤링 통합
```

기업마당과 화성시청을 같이 보는 서비스가 없다. 이 두 개를 합쳐야 진짜 64건이 보인다.

### 축 2: 화성시 특성 — 지역을 알아야 쓸 수 있다

화성시는 동탄2신도시(고밀도 신도시 상권) · 향남·봉담(전통 읍 상권) · 산업단지가 혼재한다. 상권별 경쟁 밀도와 임대료 편차가 크다. 전국형 서비스는 이 맥락을 반영하지 못한다.

우리는 화성시 4개 상권 데이터를 직접 구성했다 (예비창업자·탐색자용 상권분석 뷰). 실제 공공데이터 연동은 2차 목표이며, 현재는 구조를 검증한 목업이다.

⚠️ "상권분석 데이터가 실시간 실제 데이터"라고 말하지 말 것 — 현재는 목업.

### 축 3: UX 설계 — 챗봇에 진입장벽이 있다는 걸 알고 풀었다

AI를 붙이는 것보다 어떻게 붙이느냐가 어렵다. 우리는 세 가지로 풀었다:

- 온보딩: 한 화면에 다 묻지 않고 순서대로 (진입 부담 분산)
- 챗봇: Quick Question 버튼 (뭘 물어야 할지 모르는 상황 제거)
- 공고 화면: 행정용어 hover 툴팁 (어려운 말을 그 자리에서 해결)

### 보조 차별점 (이미 pt.md에 있음)

```
실제 데이터   샘플이 아니라 진짜 공고 29건. 매일 새벽 GitHub Actions 자동 갱신
조건 매칭     키워드 검색이 아니라 자격요건을 읽어서 판정
직접 조사     고시공고 9,458건을 실제로 훑어 문제를 수치화
```

**"매일 자동 갱신"을 빼지 말 것.** 해커톤 결과물은 대개 데모 후 데이터가 멈춘다. 우리는 GitHub Actions로 매일 새벽 자동 갱신된다.

**문장 넣지 말 것.** 숫자 하나, 라벨 하나. 설명은 전부 말로.

     5.4조 원                    3.2%

비율과 절대수를 한 장에 섞지 않는다. 한 슬라이드 = 한 메시지.
