# 기술 선택 근거 — 발표용 요약

## 1. LLM: Gemini → Groq 전환 이유

처음엔 Gemini(`gemini-3.6-flash`)로 시작했으나 벤치마크 진행 중 일일 한도에 걸렸다.

| | Gemini (무료) | Groq (무료) |
|---|---|---|
| 일일 한도 | **20 req/day** | **14,400 req/day** |
| 모델 | gemini-3.6-flash | llama-3.3-70b-versatile |
| 지연 시간 | 보통 | 빠름 (LPU 하드웨어) |

**말할 내용:** "벤치마크 테스트 중 하루 20건 한도에 걸려 다음 날까지 멈춰야 했습니다. 발표 당일 심사위원이 여러 번 눌러보는 상황에서 20건은 치명적이라 Groq으로 바꿨습니다."

## 2. RAG: 임베딩 말고 키워드를 쓴 이유

**같은 LLM, 같은 5개 질문**으로 4가지 방식을 직접 비교했다.

| RAG 방식 | Hit@1 | 환각 억제 (F3-03) |
|---|---|---|
| **키워드 substring** | **1.0** | **성공** |
| BGE-M3 임베딩 | 0.8 | **실패** |
| KoSimCSE-RoBERTa | 0.8 | — |
| KR-SBERT | 0.8 | — |

**왜 임베딩이 환각을 못 막았나 — F3-03 케이스:**

> 질문: "화성시 소상공인 자금지원사업 금리가 정확히 몇 %예요?"

| | 키워드 RAG | BGE-M3 |
|---|---|---|
| 검색 결과 1위 | `소상공인` (직접 매칭) | `미소금융` (의미 유사) |
| LLM 답변 | "공고 또는 담당 기관에 확인 필요" | **"연 1.5%~3.5%"** (환각) |

BGE-M3는 "소상공인 금리"와 의미가 가장 가까운 미소금융을 가져왔는데, 미소금융 항목엔 금리 정보가 있어서 LLM이 그걸 화성시 사업 금리로 오용했다.

**말할 내용:** "임베딩이 더 발전된 기술이지만, 우리 코퍼스는 57개 전문 용어라 사용자가 단어를 직접 말합니다. 이 조건에서 키워드가 Hit@1 1.0으로 더 정확했고, 환각 억제에서도 더 안전했습니다. 코퍼스가 수천 개로 늘면 BGE-M3로 전환할 준비는 되어 있습니다."

## 3. 모델 크기: 7B 말고 70B를 쓴 이유

로컬 Qwen2.5-7B와 Groq LLaMA-3.3-70B를 동일 조건으로 비교했다.

| | Groq LLaMA-3.3-70B | Qwen2.5-7B (로컬) |
|---|---|---|
| URL 포함률 | **4/5** | 1~2/5 |
| 프롬프트 지시 이행 | 우수 | 미흡 |
| 환각 억제 (F3-03) | 성공 | 성공 |
| 인프라 | 없음 (API) | 서버 필요 |

7B도 환각 억제는 된다. 그러나 "이 URL을 반드시 포함해라", "미검증이면 경고 문구를 달아라" 같은 구체적인 지시 이행은 70B와 차이가 났다.

**말할 내용:** "소상공인 입장에서 URL 하나의 차이가 실질적인 도움의 차이입니다."

---

## 4. temperature=0을 고정한 이유

같은 입력에 항상 같은 출력이 나와야 벤치마크 비교가 의미 있다. 모든 LLM 호출에 temperature=0을 고정해 재현 가능성을 확보했다.

## 발표 흐름 제안

1. **"모든 선택에 실험 근거가 있습니다"** 로 시작
2. Groq 선택 → 20 vs 14,400 (숫자)
3. 키워드 RAG → Hit@1 1.0 vs 0.8 + F3-03 케이스 (임팩트 최대)
4. 70B → URL 포함률 차이
5. **마무리 한 줄:**

> "Groq: 20 vs 14,400 — 숫자로 증명 / 키워드 RAG: Hit@1 1.0 vs 0.8 + 환각 F3-03 — 실험으로 증명 / 70B: URL 4/5 vs 1~2/5 — 비교로 증명"
